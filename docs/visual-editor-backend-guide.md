# Visual Editor — Capabilities & Limitations (Backend Guide)

Audience: backend developers who consume SCXML produced by the SCXML Visual Editor (the file the host gets from `window.ScxmlEditorAPI.getScxml()` or a download).

**Last verified against source:** commit `7b894f8` (main). Every claim below was checked in `src/`; file references are given so it can be re-checked. Where `.claude/` docs disagree with the code, the code wins (see [Doc drift](#doc-drift-found-while-verifying)).

## How to read the status tags

| Tag | Meaning |
|---|---|
| **ENFORCED** | The UI blocks it, or the editor rewrites the document so it cannot persist. |
| **FLAGGED** | The validator reports it (error or warning) but the document is still saved/exported. |
| **UNSUPPORTED** | The editor has no way to author it. Hand-edited XML may contain it (see "preserved or lost?"). |
| **UNVERIFIED** | Not confirmed in code; do not rely on it. |

**The one rule that matters most:** the validator never blocks anything. Validation only runs in the browser, results are advisory, and `getScxml()` returns the document even with errors. The backend must re-validate; the guarantees below are about what the *UI gestures* produce, not about what a file can contain (users can also hand-edit XML in the Monaco tab, upload files, or pull from GitHub).

## 1. What the editor supports

### 1.1 Document root
- Root is `<scxml xmlns="http://www.w3.org/2005/07/scxml" xmlns:viz="http://visual-scxml-editor/metadata" version="1.0" datamodel="ecmascript" name="main" initial="main_region">` for a new document, with one empty `<state id="main_region">` (`src/lib/consts/default_scxml_template.ts`).
- Schema-recognised root attributes: `xmlns, version, datamodel, initial, name, binding, exmode` (`attribute-schemas.ts`).

### 1.2 Elements the editor can **create** through the UI

| Element | How | Notes |
|---|---|---|
| `<state>` (simple/compound) | "Add State" button (`state_1`, `state_2`, …), paste, drag-to-nest | Compound = a state that has children (via drag-to-nest/paste). |
| `<parallel>` | **Never directly.** Created automatically when a container has 2+ disconnected Initial-State groups (see 3.2) | `<parallel>` ↔ `<state>` flips automatically as groups appear/disappear. |
| `<final>` | "Final State" checkbox in the State Actions panel (`ChangeStateTypeCommand`), or paste | **Only inside a `<parallel>`**, never a region itself, max one per container, not Initial (`checkCanMarkFinal`). |
| `<transition>` | Drag between handles; edit in Transition panel | Event, cond, or `after X` timer; targets only (see 1.4). |
| `<onentry>/<onexit>` with `<assign>` | State Actions panel | Only `assign` rows can be *added* in the panel (see 1.5). |
| `<send delay|delayexpr>` + `<cancel>` | Generated by the `after X` timer syntax | See 1.4. |
| Reaction transitions (targetless, with `<assign>` children) | State Actions → "Reactions" tab | See 1.5. |
| `<data id="conf_*" expr confType>` | Config panel | `confType` ∈ `int, double, bool, string`. |
| `<data id="this_*">` channels | Created from the Transition/Actions panel "new channel" suggestion | `expr` is a generated zero value (see 4.3). |
| `viz:*` attributes and `<viz:note>` | Layout, colours, anchors, waypoints, sticky notes | Visual only (section 5). |

### 1.3 Elements the editor can **load, display and validate** but not author
`<history>` (shallow/deep, drawn as a dashed wrapper box), `<initial>` child elements, `<invoke>`, `<donedata>`, `<datamodel>` inside states, `<script>`, `<raise>`, `<log>`, `<if>/<elseif>/<else>`, `<foreach>`, `<param>`, `<content>`, `<finalize>`. Required-attribute and unknown-attribute checks exist for all of them (`attribute-schemas.ts`, `w3c-validator.ts`). No creation gesture exists for any of these (`StateTag` is `'state' | 'parallel' | 'final'` — `scxml-manipulation-utils.ts:21`).

> **Dialect note:** a legacy `<initial>` child element is accepted on load; the editor's own `initial="..."` attribute is what it writes. (Per the repo's backward-compat docs `<initial>` is rewritten to an attribute; not re-verified here.)

### 1.4 Transitions
- **Event** transition: `event="a"`; multiple events are a **comma-separated** list (`"a, b"`) — a space is part of a name, not a separator.
- **Condition** transition: `cond="..."`. A transition may not have both `event` and `cond` (see 2.2).
- **Eventless ("always")** transition: neither attribute. A freshly drawn connection is eventless unless the source is a compound state with a `<final>` child inside a parallel, or a `<parallel>` whose regions can all finish — then it defaults to `event="done.state.<sourceId>"` (`getDefaultNewTransitionEvent`).
- **Timer** transition, authored as `after 2s`, `after 714ms`, `after (expr) s`, `after expr ms`. Stored as:
  - `<transition event="{stateId}_t_{N}_timeEvent_{N}" target="…"/>`
  - `<onentry><send event="{same name}" delay="2s"/></onentry>` (or `delayexpr="…"`)
  - `<onexit><cancel sendid="{same name}"/></onexit>`
  - `s`-unit **expressions** get `* 1000` appended to `delayexpr`; `ms` expressions are stored verbatim. The runtime reads a bare `delayexpr` as milliseconds. (`time-transition.ts`)
  - The `<send>` has **no `id` attribute**; `<cancel sendid>` holds the *event name*. Backends that match `cancel@sendid` to `send@id` per the W3C spec will not find a match.
- `type="internal"|"external"`; `internal` may only target its own source (FLAGGED otherwise).
- **Merging on load:** upload, GitHub pull, paste into the code editor, (but not host `loadScxml`, see 3.6) normalise duplicate transitions: same source+target+type+identical actions → events are comma-joined when `cond` is identical; otherwise conds are OR-combined as `(a) || (b)` (an unconditional member makes the result unconditional). (`transition-merge-utils.ts`)

### 1.5 State actions
- State Actions panel **row types: `assign`, `send`, `cancel`** (`ActionRow`). In practice a user *adds* `assign` rows; `send`/`cancel` rows exist for existing documents and timer generation.
- `assign` to a new channel auto-creates `<data id="this_…" expr="false|0.0|0">` and later re-types it from the assigned expressions (`inferChannelRetypes`).
- **Reactions** (Reactions tab): `<transition event="E" type="internal|external">` with `<assign>` children and **no `target`**. Rows with the same event are grouped into one transition and inserted before targeted transitions. Not allowed on `<final>`.

### 1.6 Hierarchy
Nested `<state>` to arbitrary depth, shown one level at a time (drill-down). Sibling-only transitions (2.1). Multiple Initial states per container (3.2). Ids are free text, **may contain spaces**, and are used as-is as the label.

### 1.7 Host-supplied data (not stored in the SCXML)
| Data | API | Stored in `.scxml`? |
|---|---|---|
| Physical channels (`ChannelInfo`: `ch,in,out,st,cf,th,dm`) | `setChannels` | No |
| Channel mappings (`scxmlRef → mappedChannel`) | `set/getChannelMappings` | **No** — only in the host store (the panel never edits content) |
| Operator events / "User Actions" (`EventEntry`) | `set/getEvents` | **No** |
| Config overrides | `setConfigValues` / `getConfigValues` | No — `conf_*` defaults live in `<data>`, overrides are host-side |

`getChannelMappings()` returns only mappings whose `scxmlRef` is *currently* unresolved in the document.

## 2. Validation rules

Source: `src/lib/validators/*`, orchestrated by `SCXMLValidator.validate`. Runs ~500 ms after edits, **only if the XML parses**. 13 passes run in isolation (a throw becomes one "could not run" warning) plus the nested-parallel pass. Output is a flat list; nothing blocks save/export.

### 2.1 Errors (severity `error`)

| Rule | Detail |
|---|---|
| Root `xmlns` | Must be exactly `http://www.w3.org/2005/07/scxml` |
| Root `version` | Required (any value) |
| Root content | Needs `initial` or at least one `state`/`parallel`/`final` |
| Root `binding` | Must be `early` or `late` |
| Missing `id` | `<state>`, `<parallel>`, `<final>`, `<history>`, `<data>` |
| Missing required attrs | `transition@target` (unless `type="internal"`), `<initial>` must contain `<transition>`, `invoke` needs `type` or `src`, `assign@location`, `send` needs `event` or `eventexpr`, `cancel` needs `sendid`/`sendidexpr`, `raise@event`, `log@expr`, `if/elseif@cond`, `foreach@item`+`@array` |
| `<final>` with `<transition>` | Error at any depth |
| Unresolved reference | Root `@initial` id; any `transition@target` id; `@initial` of **root-level states only** |
| Duplicate ids | State/parallel/final ids document-wide; `<data>` ids across all datamodels (position = last occurrence) |
| Compound state without `initial` | State with children needs `@initial` or `<initial>` |
| Transition `type` | Must be `internal`/`external`; `internal` may target only itself |
| `<script>` | Needs `src` or text |
| Unknown attribute | Against the whitelists in `attribute-schemas.ts`; namespaced (`viz:x`) attributes and `xmlns` are exempt; `confType` allowed on `<data>`; did-you-mean hint (Levenshtein ≤ 2) |
| Cross-hierarchy transition | Source and target must have the **same parent** (see below) |
| Slot conflicts | See 2.2 |
| Initial-group conflict | Two Initial states connected by a transition (directly or indirectly) |
| 2+ Initial groups + `<final>` children | Can't become a parallel |
| Nested `<parallel>` | A `<parallel>` anywhere inside another `<parallel>` |

**Cross-hierarchy detail (`transition-validator.ts`):** the rule compares `parent(source) !== parent(target)`. This also rejects parent→own-child and child→parent transitions and anything crossing a parallel region boundary. Self-transitions pass.

### 2.2 Transition slots (error)
Grouped per `(source, target, type)`; each of `event`, `timer`, `cond`, `always` may hold **at most one** transition. Plus: `event` and `cond` together is always an error; and per source state, at most one transition may use any given `done.state.<id>` event (a second can never fire). (`transition-slot-rules.ts`, `transition-slot-validator.ts`)
→ Different targets, or different `type`, may reuse the same event. The same event to two different targets is **not** flagged (only `done.state.*` is).

### 2.3 Warnings (severity `warning`)

| Rule | Detail |
|---|---|
| `datamodel` value | Not `null`/`ecmascript`/`xpath` |
| Unreachable state | Id is never an `initial` value or a transition target. See limitation L5. |
| `main_` prefix | One warning **per occurrence** (declaration or expression reference); suggests `this_` |
| Event name syntax | Each comma-separated token must be `*`, or match `^[a-zA-Z_][a-zA-Z0-9_\-\. ]*(\.\*)?$` (letters, digits, `_ - . space`; no leading digit). Anything else, e.g. `a<=3`, `1`, `a:b`, is a warning |
| Validation pass crash | "Some checks (…) could not run on this document" |

### 2.4 Live (gesture-time) blocks — not file-level guarantees
Blocked with an in-app message and never written: duplicate-slot transitions, event+cond together, a second `done.state.X` transition, connections from a `<final>`, connecting two different Initial groups, a transition crossing parallel regions (`parallel-region-connection-validation.ts`), nesting a `<parallel>` in a `<parallel>`, marking Final outside a parallel / twice in one container / on an Initial state.

## 3. Backend implications

### 3.1 What you can safely assume about UI-produced output
1. Namespace and `version` are present (template-seeded); `viz:` namespace is declared on documents the editor creates.
2. Every `<state>/<parallel>/<final>` the editor creates has a unique `id` (`state_N` auto-ids avoid collisions; synthetic ids are collision-checked, `_2` suffix).
3. Transitions are same-parent only, and each (source, target, type) holds at most one transition per slot.
4. `<final>` appears only inside `<parallel>` (UI path), never as a transition source.
5. No `<parallel>` is nested in another `<parallel>` (UI path).
6. Timer transitions always come as the `event` + `<send delay>` + `<cancel>` triple above; delay expressions are already in **milliseconds**.
7. `conf_*` data have an explicit `confType`.

### 3.2 Editor-generated structure you must handle
Marking 2+ disconnected children of a container as Initial **rewrites the document** (`parallel-group-normalization.ts`):
- A compound `<state>` with 2+ Initial groups becomes the `<parallel>` itself (same id); its `initial` is removed.
- Each group is wrapped in a synthetic region `<state id="{initialId}_region" initial="{initialId}">`.
- At `<scxml>` level the regions go in `<parallel id="__root_parallel">` (suffix `_2`… on clash) because the root can't be a parallel; `scxml@initial="__root_parallel"`.
- If the container also has "loose" (unassigned) children, regions go in `<parallel id="{stateId}__parallel">` beside them, and the container's `initial` points at it.
- A `<parallel>` with < 2 regions reverts to `<state>` (and a hollow region is deleted). **This applies to hand-written `<parallel>` too** — the editor will restructure such a file on load/edit.
- These ids are reserved patterns (`__root_parallel`, `*__parallel`, `*_region`); treat them as ordinary states in the engine.

### 3.3 Event and identifier handling
- Events: comma = separator; spaces inside names are allowed; `done.state.<id>` is used for completion; timer events follow `{stateId}_t_{N}_timeEvent_{N}`.
- **Renaming a state** also rewrites inbound `target`s, `initial` tokens, its own timer event/`send`/`cancel` tokens, and every `done.state.<oldId>` token. But note the merge code splits events on commas **and whitespace** (`combineEvents`, `getNextTransitionEventName`) — so event names containing spaces can be split into separate events by the load-time merge (UNVERIFIED end-to-end; derived from code).
- Default names for new events are `event1`, `event2`, …
- The downstream **C# generator** rules in `docs/invalid-event-identifiers.md` (no empty event, no C# keywords, no leading digit, no wildcard `assign@location`, no events that collapse to the same string after punctuation stripping, every assigned variable declared in `<datamodel>` and in `IO.conf`) are **mostly not enforced** by the editor. See section 4.

### 3.4 Variables / datamodel conventions (naming only, not schema-enforced)
| Prefix | Meaning | Editor behaviour |
|---|---|---|
| `conf_` | Per-deployment config value (`IO.Conf`) | Config panel; deletion refused while referenced; type via `confType` |
| `this_` | Local channel owned by this machine | Auto-declared with zero literal: `false`→bool, `0.0`→double, `0`→int. The C# generator infers the field type from the literal and rejects non-config strings, so everything else becomes `int` (`datamodel-extractor.ts`) |
| `main_` | Ties a name to one specific machine | Warning only |
| anything else not declared | "Unresolved channel" | Shown in Channel Mapping panel; mapping is host-side only, **the SCXML still contains the raw name** |

### 3.5 Export forms
- `getScxml()` and "Download" return the **live content including `viz:` metadata**.
- "Download Clean" re-serialises without `viz:`. Fallbacks: regex strip if parse fails; and if both throw, the *original un-stripped* content is downloaded under the "clean" name (`use-download.ts`). A backend that cannot tolerate `viz:` should strip/ignore it itself. `viz:` attributes/`<viz:note>` are the only extension namespace; they're valid on any element for the validator.
- `<viz:note>` can appear as a child of the root or a state and carries free text.

### 3.6 Host API surface (embedding)
`window.ScxmlEditorAPI`: `onReady, loadScxml, getScxml, getConfigValues, setConfigValues, registerCommand, showFeedback, setChannels, toggleConfigPanel, getChannelMappings, setChannelMappings, toggleChannelMappingPanel, setActiveTab, setEvents, getEvents, toggleEventsPanel, showErrors, clearErrors` (`src/types/host-api.ts`).
- Call everything from inside an `onReady` callback. The pre-mount stub only has `onReady, registerCommand, showFeedback, setChannels, showErrors, clearErrors, loadScxml, getScxml, toggleConfigPanel, setActiveTab`.
- Pre-mount `loadScxml()` is a **silent no-op**, pre-mount `getScxml()` returns `''`, and any other method throws `TypeError` (`pre-ready-stub.ts`).
- `showFeedback(msg, 'error')` is converted into a persistent Host Alerts entry and the toast text is fixed ("Host reported an error…").
- `loadScxml` annotates `conf_` types and resets history/validation, but does **not** run the duplicate-transition merge that upload/GitHub do; `normalizeParallelGroups` still runs via `setContent`.

## 4. Known limitations & gaps (editor allows ↔ backend/validator can't handle)

| # | Gap | Status | Evidence |
|---|---|---|---|
| L1 | **Panel edit destroys unsupported actions.** Any apply in the State Actions panel rewrites the whole `<onentry>`/`<onexit>`. Only `assign`, `send`, `cancel` survive the round trip into the panel's rows; `raise`, `log`, `script`, `if`, `foreach` in `onentry`/`onexit` are silently dropped. Also, multiple `<onentry>` blocks are merged into one. | UNSUPPORTED + data loss | `visual-diagram.tsx` `parseActions` returns `[]` for other tags; `update-actions-command.ts` |
| L2 | Same command fabricates a **non-SCXML `<executable label="Action" expr="…"/>`** element for any action string it doesn't recognise (e.g. a `send|…` string in `onexit`, a `cancel|…` string in `onentry`), and writes `log` as `<log label="Action" expr="<whole pipe string>"/>`. Not reachable from the panel UI as normal use, but it is what the command does for such input. | UNVERIFIED reachability | `update-actions-command.ts:83-93,119-129` |
| L3 | **Reaction transitions with `type="external"` and no target trigger the validator error** "Missing required 'target'" (only `internal` is exempt), though the Reactions tab can produce them. | FLAGGED (self-inflicted) | `w3c-validator.ts:293`, `update-internal-events-command.ts` |
| L4 | Transition-level executable content (`<transition><assign/></transition>` beyond reactions) has no editing UI. `<transition>` children are not part of the type model the panel reads. | UNSUPPORTED | `transition-merge-utils.ts` comment; Transition panel edits event/cond/target only |
| L5 | **Unreachable-state check is approximate**: a state is "reachable" if it is any `initial` value or any transition target; it does not follow reachability from the entry point, and ignores W3C "first child is default initial". A state without `initial` ancestry that nothing targets is warned. Children of `<parallel>` are only reachable if some `initial`/target names them. | FLAGGED (may be noisy) | `state-validator.ts findReachableStates` |
| L6 | Nested (non-root-level) `@initial` pointing at a non-existent id has **no dedicated error**; only root-level states' `@initial` and root `@initial` are checked. | Gap | `transition-validator.ts validateInitialStates` |
| L7 | A compound state *inside* a `<parallel>` missing `@initial` is not flagged (recursion follows `state→state` only). | Gap | `state-validator.ts validateCompoundStates` |
| L8 | Cross-region transitions are blocked at connect time by a dedicated live check with **no dedicated static counterpart**. A hand-edited file is still caught indirectly by the cross-hierarchy error when the regions are distinct `<state>` parents (always true for editor-made regions); other region layouts were not tested. | Partial | `parallel-region-connection-validation.ts` (live only); `validateCrossHierarchyTransitions` |
| L9 | C# generator pitfalls: empty `event=""` (falsy → never checked), C# reserved words (`event`, `class`, …), wildcard `*` in `assign@location`, event names colliding after stripping punctuation, undeclared `assign` targets (`assign@location` not checked against `<data>`). None has a rule. Leading-digit and punctuation events get only the *event-name syntax warning* above. | No rule | grep of `src/` finds no reserved-word list; `transition-validator.ts` |
| L10 | **Duplicate event → different targets** and any other W3C-legal nondeterminism are not flagged beyond `done.state.*`. | By design | `transition-slot-validator.ts` |
| L11 | The editor can't author `<history>`, `<invoke>`, `<donedata>`, `<script>`, state-level `<datamodel>`. Conversely, the **State→`<parallel>` command is not implemented**; parallels come only from the Initial-group mechanism. | UNSUPPORTED | `scxml-manipulation-utils.ts` `StateTag`; `change-state-type-command.ts` |
| L12 | `<final>` at root or inside non-parallel compound states can be **loaded** and is valid, but the UI refuses to create it there. | ENFORCED (create only) | `checkCanMarkFinal` |
| L13 | No id validation on rename: duplicates, spaces, empty or XML-hostile strings are accepted by `RenameStateCommand`; only the validator (duplicate-id error, FLAGGED) reacts afterwards. Don't assume ids are identifier-safe. | FLAGGED | `visual-diagram.tsx handleNodeLabelChange`, `rename-state-command.ts` |
| L14 | `confType="string"` fields: Config panel adds `<data … expr="{defaultValue}" confType="string"/>` by string interpolation; whether `defaultValue` is escaped was **not verified**. | UNVERIFIED | `side-panels.tsx onAddField` |
| L15 | Validation never runs server-side, never gates export, and `ValidationError.code` is never populated. | By design | `use-content-validation.ts` |
| L16 | Positions of errors outside attribute checks are approximate (line-based lookup). Irrelevant to the backend unless you consume the editor's validator output. | Known | `scxml-validation.md` |

## 5. `viz:` metadata (ignore or strip)

All under `xmlns:viz="http://visual-scxml-editor/metadata"`; legacy URIs/prefixes are rewritten on write-back. Attributes: `viz:xywh="x,y,w,h"`, `viz:rgb` (hex), `viz:sourceHandle`/`viz:targetHandle` (`top|bottom|left|right`, optional `-N` index), `viz:anchors="bottom:3;right:2"`, `viz:waypoints="x,y;x,y"`, plus legacy `curve-type, marker-type, label-offset, z-index`. Element: `<viz:note>` (id prefix `note:`). Known inconsistency: some code paths write `viz:xywh` space-separated, all readers expect commas.
