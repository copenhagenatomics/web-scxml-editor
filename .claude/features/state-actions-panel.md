# Feature: State Actions Panel (onentry / onexit / Event Reactions)

## Purpose

Let a user edit a state's behavioral content — what happens on entry, what happens on exit, and how it reacts to internal events — through a structured form UI instead of hand-writing `<onentry>`/`<onexit>`/`<assign>` XML, with autocomplete over known variables/channels.

## User behavior

- Clicking a state (single click, not double) opens this panel scoped to that state, with three tabs: **onentry**, **onexit**, **event reactions**.
- Each tab lists existing action rows; clicking a row opens it for inline editing; "+" opens a blank inline form to add a new one.
- Rows can be **drag-reordered** (grip handle), **copied** (clipboard icon, cross-tab-type-aware — actions and reactions have separate clipboards), and **pasted** (only enabled when a clipboard entry of the matching kind exists).
- The panel also hosts the **"Initial State" checkbox** for simple/compound states — checking it can be blocked (disabled, with an explanatory tooltip) if doing so would merge two Initial State groups (see `initial-state-groups.md`); unchecking is always allowed.
- Typing a `this_`-prefixed identifier that doesn't match any known variable/channel in the Location or Expression field offers a highlighted "(new channel)" suggestion that, when accepted, declares it as a new datamodel field via `AddDataCommand`.
- Clicking anywhere in the panel outside an open inline form discards the in-progress add/edit (same as clicking Discard).

## UI behavior

- The onentry/onexit tabs never show the `send`/`cancel` row pair generated by an "after X" time transition (`isTimerGeneratedActionString` in `time-transition.ts`, matched on the row's event/sendid following the `_t_N_timeEvent_N` pattern) — these are edited exclusively via the Transition panel's "after X" field. `visual-diagram.tsx` filters them out before constructing the panel's props, then re-appends the filtered-out raw strings to whatever the panel applies (`onApply`, `onNewChannel`) so an edit to an unrelated row never drops the timer's underlying `send`/`cancel` elements from the SCXML. Same filtering hides them from the state node's `entry:N`/`exit:N` canvas indicator (`scxml-state-node.tsx`). The code editor (Monaco) is unaffected — the elements are still written to the document.
- Only assign-type action rows are copyable (send/cancel rows have no copy button) — `handleCopyRow` returns early for non-`'assign'` rows.
- The Expression field's autocomplete dropdown live-previews the highlighted suggestion spliced into the text as you arrow through it, without committing until Tab/Enter.
- Reaction rows show event name + type badge (`internal`/`external`) + `location = expr`, left-aligned (`align='start'`) since reactions can wrap to two lines; regular action rows are vertically centered.

## Internal architecture

- Actions are round-tripped as **pipe-delimited encoded strings** at the Command boundary (`"assign|location|expr"`, `"send|event|delayType|delayValue"`, `"cancel|sendid"`) — the panel's internal `ActionRow` union is richer/typed, but `toStrings()` flattens it to this string format before calling `onApply(entryActions: string[], exitActions: string[])`.
- Rows have **no persistent identity in the SCXML source** (they're plain tuples/attributes, not elements with ids) — the panel attaches a client-only `_rowId` (via `withRowIds`) specifically so React/dnd-kit can track a row's identity across a reorder without recycling identity by array index (index-as-id previously caused the dragged row to visually snap back before jumping — see the file's own comment).
- Two **independent autocomplete engines** run in this one panel: the Location field (single-identifier suggestions, `Suggestion` type) and the Expression field (multi-token expression suggestions via `getExpressionSuggestions`/`applyExpressionSuggestion` from `expression-autocomplete.ts`) — they have separate open/active-index/blur-timer state because their token models differ.
- Applying any change immediately calls `onApply`/`onApplyReactions` (parent-supplied), which in `visual-diagram.tsx` routes to `UpdateActionsCommand` (onentry/onexit) or `UpdateInternalEventsCommand` (reactions) — **not deferred to a panel-level "Save" button**; every row add/edit/delete/reorder/paste is its own immediate commit (each becomes its own history entry via the `'property'`/`'structure'` changeType).

## SCXML behavior

- onentry/onexit tab writes/reads `<onentry>`/`<onexit>` children containing `<assign>`/`<send>`/`<cancel>`/etc. — `UpdateActionsCommand` wipes **all** existing `<onentry>`/`<onexit>` elements (there can be more than one) and writes exactly one new element per type if any actions remain.
- The "event reactions" tab manages **targetless** `type="internal"|"external"` transitions with `<assign>` children — see `.claude/project/terminology.md` "Internal event reaction". `UpdateInternalEventsCommand` groups actions **by event name** so multiple rows for the same event collapse into one `<transition event="X">` with multiple `<assign>` children, and inserts new reaction transitions before the first pre-existing targeted transition to preserve ordering conventions.

## Validation rules

None enforced *within* this panel beyond basic required-field disabling (`isApplyDisabled`) — full SCXML validation (unreachable states, slot conflicts, etc.) runs independently against whatever content results. The Initial-State checkbox's disabled state is the one exception: it proactively consults `initial-group-utils.ts` (`canMarkInitial`, passed down from the parent) to block a would-be-invalid mark before the user can even attempt it.

## Known limitations

- No bulk/multi-row selection within the panel — copy/paste/reorder/delete all operate on one row at a time.
- Send/cancel action rows cannot be copied (only assign rows) — likely intentional (a copied `send`/`cancel` referencing a specific event/sendid is less obviously reusable) but not explicitly documented as such anywhere; verify before assuming it's a bug to fix.

## Important edge cases

- Switching the active tab (`onentry`/`onexit`/`reactions`) always calls `resetForm()` — any in-progress unsaved add/edit is silently discarded, with no confirmation prompt.
- Switching to a **different state** (`stateId` prop change) resets `localEntry`/`localExit`/`localReactions` from the newly-passed initial props and resets the form — the panel does not preserve an in-progress edit across a state-selection change.
- The "new channel" suggestion only appears when the combined variable+channel suggestion list is otherwise **empty** and the typed text starts with `this_` — typing `this_` when it happens to partially match an existing channel/variable name will show that match instead of the new-channel option.

## Things that must NOT be changed

- Do not switch row identity back to array index for drag-reordering — the `_rowId` (uuid) approach exists specifically to fix a visual snap-back bug with dnd-kit; this is documented in the file's own comment, not incidental.
- Do not change the pipe-delimited action string encoding (`"assign|location|expr"` etc.) without updating both `toStrings()` in this panel and the corresponding parser in `UpdateActionsCommand`/`extractActionsFromElement` — they must stay in sync.
